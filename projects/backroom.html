Backroom In progress

A game master tool that surfaces your own prepped ideas mid-session.

Status
In progress, with a public demo
Runs
Locally, no AI service
Built with
TypeScript, Node, local embeddings

The problem

A game master prepares far more than a single session can use, and the prep lives in notes. Mid-session, when the table does something unexpected, the useful idea is somewhere in those notes and there is no time to look for it.

The story behind it: how you ran into this problem yourself, in a sentence or two.

Who it is for

Game masters who keep their prep as Markdown notes and want to find the right idea for the scene in front of them while the session is running.

Who actually tried it, if anyone has: how many game masters, and what system or campaign they run.

Key decisions and tradeoffs

Find the game master's own ideas, never generate new ones

Chose
Search and rank text the game master already wrote. It generates nothing and calls no AI service.
Because
The value is recalling prep you trust, in your own words and your own world, not receiving someone else's suggestions.
Cost
It can only be as good as the notes behind it, and new notes need a re-index before they can be found.

Run locally

Chose
Notes are only read, and the index, usage state and logs stay in the project folder. The only network access is a one-time download of a small embedding model (about 25 MB).
Because
Campaign notes are personal, and a tool used mid-session should not depend on a connection.

One idea per result

Chose
Split notes on headings, paragraphs and top-level bullets, keep a bullet's indented children with it, and show each result with its note, heading and line numbers.
Because
A result has to be readable at a glance and traceable back to where it was written.

Be honest about relevance

Chose
Show how far above the average idea in the notes a match scores, and draw a divider where relevance drops sharply.
Over
Presenting a ranked list as if every row were a good answer.
Because
At the table, you need to know when to stop reading the list.

Track what gets used

Chose
A "mark used" button, an "unused only" filter, and a boost for old prep that has never been used. Usage is keyed on the idea's text, not its line number, so marks survive edits elsewhere in the note.
Because
Prep that is never used is the thing worth resurfacing, and it is the signal for what to improve next.

A public demo that cannot leak private notes

Chose
The demo ships a precomputed index, runs the search in the visitor's browser, and makes no outside requests. The build refuses any folder other than the sample notes unless explicitly overridden.
Cost
The first visit downloads about 36 MB for the model and runtime, then the browser caches it.

Results so far

It works end to end: a local web page and command-line tools for search, marking ideas used and re-indexing, backed by an automated test suite, plus a public demo built from a small sample of invented world notes.

Any usage or feedback numbers once you have them (sessions run, ideas surfaced and marked used, how fast a search feels).

What I would do next

  • Run it in real sessions and use the "mark used" data to learn which kinds of ideas get used and which are never found.
  • Tune the ranking and the relevance divider against those sessions instead of my own guesses.
  • Pick up changed notes without a manual re-index.
