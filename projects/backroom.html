Backroom in progress

A tool for tabletop game masters. TypeScript and Node, with a public demo.

What it does

You type what is happening at the table, and Backroom finds the notes you already wrote that fit the scene. Each result is one idea from your own notes, shown with the note it came from, its heading and its line numbers, so you can see where it lives. You can mark an idea as used and hide the ones you have used. You can also give old prep that you never got to a small boost, so it comes back around.

Why I'm building it

A game master prepares far more than a session can use, and all of it sits in notes. When the table does something unexpected, the idea that would fit is in there somewhere, and there is no time to look for it in the middle of play.

I've been on the wrong end of this myself. In one session a supposedly level 3 wizard started flying, and I forgot about the trap I had set in the alleyway. I managed to scrape together a sudden fight, and while the players were celebrating I quickly rewrote my next session's plans so that it took place right after.

Who it is for

Game masters who keep their prep as Markdown notes and run live sessions.

What it will not do

Backroom only finds and ranks text you wrote. It does not generate plots, characters or descriptions, it does not rewrite your notes, and it does not send them anywhere. It runs on your own computer. The first time you start it, it downloads one small language model of about 25 megabytes, which it uses only to compare how similar two pieces of text are.

That comparison is the only job any AI has here, and I want to keep it that way. A game master's world only holds together if its facts agree with each other, and a model that has not read the whole campaign would add contradictions without anyone noticing. A result that is your own sentence, with the note it came from, is something you can trust at the table without checking it. Generated text would not be. If I ever add more AI, it will be limited to looking after your own notes, and it will not write your story.

How I will know whether it works

Backroom already records which results a game master marks as used, and that is the signal I care about most. I want to know how often a search ends with an idea being marked as used, and how fast the search comes back, since it has to feel instant in the middle of a scene. I have not measured either in real sessions yet. For a sense of speed, building the demo index from five sample notes took about 0.6 seconds.

Where it stands

It works from start to finish. There is a local web page and a set of command line tools for searching, marking ideas as used and re-indexing, with an automated test suite behind them, and a public demo that runs in the browser on invented sample notes. Next I want to run it in real sessions, see which ideas get found and which never do, and tune the ranking against that. It also needs to pick up changed notes without a manual re-index.
