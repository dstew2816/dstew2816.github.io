Backroom In progress

A product brief for a game master tool that surfaces your own prepped ideas mid-session.

Status
In progress, with a public demo
Runs
Locally, no generative AI
Built with
TypeScript, Node, local embeddings

The problem

A game master prepares far more than a single session can use, and the prep lives in notes. Mid-session, when the table does something unexpected, the useful idea is somewhere in those notes and there is no time to look for it. The prep exists, but it is not available when it matters.

Who it is for

Game masters who keep their prep as Markdown notes and run live sessions, where attention is the scarce resource. They need an answer in seconds, in their own words, without leaving the scene.

Scope

In scope now

  • Type the current scene and get the most relevant ideas from your own notes, each with its note, heading and line numbers.
  • Mark an idea as used, filter to unused ideas, and give old unused prep a small boost.
  • Re-index changed notes.
  • Run entirely on your machine. A public demo runs the same search in the browser on invented sample notes.

Out of scope

  • Generating plots, characters, descriptions or any new content.
  • Editing or rewriting the game master's notes.
  • Sending notes to an outside service.

The principle: AI maintains, never writes your story

For now, the tool does one thing: it pulls relevant notes and ideas the game master already wrote. It generates nothing. It uses no generative AI at all; a small local model is used only to measure how similar two pieces of text are. If AI ever does more, it will be limited to looking after the game master's own material, and it will never author the story.

I held this line for three reasons.

  • Trust at the table. A game master has to be able to act on a result without checking it. A result that is their own sentence, with the note and line it came from, needs no checking. Generated text would.
  • The world stays coherent. A campaign only works if its facts agree with each other. New text from a model would not know the world, and would quietly add contradictions.
  • The value is recall, not invention. Game masters do not lack ideas. They lack access to the ones they already had.

How I would know it works

The tool already records which results a game master marks as used. That is the product signal. The questions I would track:

  • How often a search leads to an idea being marked used.
  • How much old, never-used prep gets surfaced and used, since resurfacing it is the point.
  • How long a search takes, because a tool used mid-session has to feel instant.

I have not yet measured these with real sessions. For scale, building the demo index from 5 sample notes (29 ideas) takes about 0.6 seconds.

Status and next

It works end to end: a local web page and command-line tools for search, marking ideas used and re-indexing, backed by an automated test suite, plus the public demo.

  • Run it in real sessions and use the "mark used" data to see which ideas get found and which never do.
  • Tune the ranking and the point where relevance drops off against those sessions.
  • Pick up changed notes without a manual re-index.
